# Residual conduct rules

> **Status:** drafted 2026-11-08, awaiting the operator's sign-off. v1 scope A7.

These are the rules no control RatchetHub (RH) generates can reach. They are **residue, not
controls** (charter C6): nothing enforces them, and RH's report lists them under that heading so
nothing claims otherwise. Each exists because a control stops at a known edge, which the rule names.
A project's own conduct rules stay with that project (v1 scope §1).

## 1. A refusal is handed over, never routed around

When the sandbox, a permission rule or a hook refuses, report it and stop. Trying another spelling, tool or channel after a refusal is evasion, however sure the agent is it was wrong.

## 2. Propose a change to the controls; never apply one

The agent's part in a change is a proposal a person applies (protocol §2). It writes the declaration change as text, never by any route around the floor.

## 3. Never hand a person a form the agent may not run

A deny rule or hook stops the agent running a command, not printing it. A refused form is refused for the person's terminal too; the drivers' REST paths are the route.

## 4. Relay a driver's handoff block exactly

Copy the block as printed, step tag included. The relay guard blocks a changed line once per emission and then stands aside, so the rule carries the rest.

## 5. No route the guards can't see

Don't reach GitHub's write API with curl, wget, a web fetch or a script, and don't assemble a command from variables. The hooks read the command line; these forms pass them unread.

## 6. Measure a capability before stating it

Run `ratchethub probe`, then speak. One failed call is not a limit: retry it and try an independent channel. A row the probe only inspected was not exercised.

## 7. State every control at its real strength

In prose as in the report: a tripwire is never a barrier, a detective control never a preventive one, and a row not yet probed live is not enforced.
